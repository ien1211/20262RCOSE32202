## 1. 운영체제의 역할과 실행 모드

운영체제는 CPU, 메모리, 저장장치 등의 자원을 관리하고 프로그램에 실행 환경을 제공합니다.
프로세스 스케줄링, 메모리 관리, 파일 관리, 장치 접근 및 보호가 대표적인 기능입니다.

| 구분 | 의미 |
| --- | --- |
| 사용자 모드 | 일반 응용 프로그램이 실행되는 제한된 권한의 모드 |
| 커널 모드 | 커널이 자원 관리와 특권 작업을 수행하는 모드 |
| 시스템 콜 | 사용자 프로그램이 커널 서비스를 요청하는 인터페이스 |

사용자 프로그램이 시스템 콜을 호출하면 제어가 커널로 넘어갑니다. 이때 모드가 바뀌더라도 반드시 다른 프로세스로 전환되는 것은 아닙니다.

## 2. 커널 구조

| 구조 | 특징 | 장점 | 고려할 점 |
| --- | --- | --- | --- |
| 모놀리식 커널 | 여러 운영체제 서비스가 커널 공간에서 실행됨 | 서비스 간 직접 호출로 통신 비용을 줄일 수 있음 | 커널 내부 오류가 시스템 전체에 영향을 줄 수 있음 |
| 마이크로커널 | 최소 기능을 커널에 두고 여러 서비스를 사용자 공간으로 분리함 | 서비스의 격리와 교체에 유리함 | 메시지 전달 및 실행 전환 비용이 발생할 수 있음 |

실제 운영체제는 다양한 설계를 결합하므로, 이름만으로 성능이나 안정성을 단정하지 않고 서비스 배치와 통신 방식을 함께 살펴봐야 합니다.

## 3. 인터럽트, 예외, 시스템 콜

| 종류 | 발생 원인 | 예시 |
| --- | --- | --- |
| 하드웨어 인터럽트 | 현재 명령어 실행과 비동기적으로 외부 장치 등이 알림 | 타이머, 장치의 I/O 완료 |
| 예외 | 현재 실행 중인 명령어와 관련된 동기적 사건 | 잘못된 명령어, 페이지 폴트 |
| 시스템 콜 | 프로그램이 의도적으로 커널 서비스를 요청 | 파일 읽기, 프로세스 생성 요청 |

처리 과정의 개요는 실행 상태 저장, 원인에 맞는 핸들러 실행, 필요한 후속 처리, 적절한 실행 위치로 복귀입니다.
사건의 종류에 따라 명령어를 재실행하거나 다음 명령어로 진행할 수 있으며, 프로세스가 종료될 수도 있습니다.

`trap`의 세부 의미는 교재와 아키텍처에 따라 달라질 수 있습니다. 시스템 콜의 제어 이전을 넓게 설명할 때 쓰는 용례와 특정 CPU의 예외 분류를 구분해야 합니다.

## 4. 프로세스 상태와 문맥 교환

- **Ready**: 실행할 준비가 되었지만 CPU 할당을 기다리는 상태
- **Running**: CPU에서 실행 중인 상태
- **Blocked / Waiting**: I/O 완료나 특정 사건을 기다리는 상태

일반적인 전이에는 Ready → Running, Running → Ready, Running → Blocked, Blocked → Ready가 있습니다.
시간 할당량 만료는 Running → Ready, 블로킹 I/O 요청은 Running → Blocked의 예입니다.

문맥 교환은 실행을 이어가기 위한 레지스터, 프로그램 카운터 등의 상태를 저장하고 다른 실행 문맥을 복원하는 작업입니다.
운영체제는 PCB 등의 자료구조를 통해 프로세스의 상태와 관리 정보를 유지합니다.

모드 전환과 문맥 교환은 다른 개념입니다. 같은 프로세스의 시스템 콜 처리 중에는 사용자 모드와 커널 모드 사이를 오가더라도 다른 프로세스로 바뀌지 않을 수 있습니다.

## 5. 프로세스 생성과 실행: fork, exec, wait

| 연산 | 핵심 의미 |
| --- | --- |
| `fork()` | 새로운 자식 프로세스를 생성함. 성공하면 부모에는 자식 PID, 자식에는 0을 반환함 |
| `exec` 계열 | 현재 프로세스의 프로그램 이미지를 새 프로그램으로 교체함. 성공하면 기존 호출 지점으로 돌아오지 않음 |
| `wait()` / `waitpid()` | 자식의 종료 등의 상태 변화를 기다리거나 확인하고, 종료한 자식의 상태를 수거함 |

`fork()`가 실패하면 부모에 -1이 반환되고 자식 프로세스는 생성되지 않습니다.
자식의 PID가 부모의 PID보다 반드시 1 큰 것은 아닙니다. PID는 운영체제의 할당 정책과 다른 프로세스의 생성 상황에 따라 결정됩니다.

`exec`는 그 자체로 새 프로세스를 만드는 연산이 아니며, 성공한 경우에도 일반적으로 현재 PID는 유지됩니다.
