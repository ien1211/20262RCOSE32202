## 1. 운영체제의 역할과 실행 모드

운영체제는 CPU, 메모리, 저장장치 등의 자원을 관리하고 프로그램에 실행 환경을 제공합니다.
프로세스 스케줄링, 메모리 관리, 파일 관리, 장치 접근 및 보호가 대표적인 기능입니다.

| 구분 | 의미 |
| --- | --- |
| 사용자 모드 | 일반 응용 프로그램이 실행되는 제한된 권한의 모드 |
| 커널 모드 | 커널이 자원 관리와 특권 작업을 수행하는 모드 |
| 시스템 콜 | 사용자 프로그램이 커널 서비스를 요청하는 인터페이스 |

사용자 프로그램이 시스템 콜을 호출하면 제어가 커널로 넘어갑니다. 이때 모드가 바뀌더라도 반드시 다른 프로세스로 전환되는 것은 아닙니다.

## 2. 커널 구조

| 구조 | 특징 | 장점 | 고려할 점 |
| --- | --- | --- | --- |
| 모놀리식 커널 | 여러 운영체제 서비스가 커널 공간에서 실행됨 | 서비스 간 직접 호출로 통신 비용을 줄일 수 있음 | 커널 내부 오류가 시스템 전체에 영향을 줄 수 있음 |
| 마이크로커널 | 최소 기능을 커널에 두고 여러 서비스를 사용자 공간으로 분리함 | 서비스의 격리와 교체에 유리함 | 메시지 전달 및 실행 전환 비용이 발생할 수 있음 |

실제 운영체제는 다양한 설계를 결합하므로, 이름만으로 성능이나 안정성을 단정하지 않고 서비스 배치와 통신 방식을 함께 살펴봐야 합니다.

## 3. 인터럽트, 예외, 시스템 콜

| 종류 | 발생 원인 | 예시 |

| 시스템 콜 | 프로그램이 의도적으로 커널 서비스를 요청 | 파일 읽기, 프로세스 생성 요청 |

처리 과정의 개요는 실행 상태 저장, 원인에 맞는 핸들러 실행, 필요한 후속 처리, 적절한 실행 위치로 복귀입니다.
사건의 종류에 따라 명령어를 재실행하거나 다음 명령어로 진행할 수 있으며, 프로세스가 종료될 수도 있습니다.

`trap`의 세부 의미는 교재와 아키텍처에 따라 달라질 수 있습니다. 시스템 콜의 제어 이전을 넓게 설명할 때 쓰는 용례와 특정 CPU의 예외 분류를 구분해야 합니다.

## 4. 프로세스 상태와 문맥 교환

- **Ready**: 실행할 준비가 되었지만 CPU 할당을 기다리는 상태
- **Running**: CPU에서 실행 중인 상태
- **Blocked / Waiting**: I/O 완료나 특정 사건을 기다리는 상태

일반적인 전이에는 Ready → Running, Running → Ready, Running → Blocked, Blocked → Ready가 있습니다.
시간 할당량 만료는 Running → Ready, 블로킹 I/O 요청은 Running → Blocked의 예입니다.

문맥 교환은 실행을 이어가기 위한 레지스터, 프로그램 카운터 등의 상태를 저장하고 다른 실행 문맥을 복원하는 작업입니다.
운영체제는 PCB 등의 자료구조를 통해 프로세스의 상태와 관리 정보를 유지합니다.

모드 전환과 문맥 교환은 다른 개념입니다. 같은 프로세스의 시스템 콜 처리 중에는 사용자 모드와 커널 모드 사이를 오가더라도 다른 프로세스로 바뀌지 않을 수 있습니다.

## 5. 프로세스 생성과 실행: fork, exec, wait

| 연산 | 핵심 의미 |
| --- | --- |
| `fork()` | 새로운 자식 프로세스를 생성함. 성공하면 부모에는 자식 PID, 자식에는 0을 반환함 |
| `exec` 계열 | 현재 프로세스의 프로그램 이미지를 새 프로그램으로 교체함. 성공하면 기존 호출 지점으로 돌아오지 않음 |
| `wait()` / `waitpid()` | 자식의 종료 등의 상태 변화를 기다리거나 확인하고, 종료한 자식의 상태를 수거함 |

`fork()`가 실패하면 부모에 -1이 반환되고 자식 프로세스는 생성되지 않습니다.
자식의 PID가 부모의 PID보다 반드시 1 큰 것은 아닙니다. PID는 운영체제의 할당 정책과 다른 프로세스의 생성 상황에 따라 결정됩니다.

`exec`는 그 자체로 새 프로세스를 만드는 연산이 아니며, 성공한 경우에도 일반적으로 현재 PID는 유지됩니다.

## 6. CPU 스케줄링과 평가 지표

아래 식은 CPU 버스트 하나만 실행하고 I/O가 없는 단순한 스케줄링 문제를 기준으로 합니다.

- **Response time** = 최초 CPU 실행 시각 − 도착 시각
- **Turnaround time** = 종료 시각 − 도착 시각
- **Waiting time** = Turnaround time − CPU 실행 시간
- **Completion time** = 해당 프로세스가 실행을 마친 절대 시각

| 정책 | 선택 기준 | 특징 |
| --- | --- | --- |
| FCFS | 준비 큐에 먼저 들어온 순서 | 보통 비선점 방식이며 긴 작업 뒤의 짧은 작업이 오래 기다릴 수 있음 |
| SJF | 준비된 작업 중 CPU 버스트가 가장 짧은 작업 | 비선점 방식. 버스트 길이의 예측이 필요함 |
| SRTF | 준비된 작업과 실행 중인 작업 중 남은 시간이 가장 짧은 작업 | 선점 방식. 더 짧은 작업 도착 시 교체할 수 있음 |
| RR | 준비 큐 순서대로 정해진 시간 할당량만큼 실행 | 보통 FIFO 준비 큐를 사용하며, 미완료 작업은 큐 뒤로 이동함 |

RR은 가장 짧은 작업을 선택하는 정책이 아닙니다. 작업이 끝나거나 블록되면 시간 할당량이 남았더라도 다음 준비 작업을 실행할 수 있습니다.

## 7. Round Robin 계산 예시

시간 할당량은 3, 문맥 교환 비용은 0으로 가정합니다. 각 프로세스는 CPU 버스트 하나만 가지며, 도착 시 준비 큐 뒤에 들어갑니다.

| 프로세스 | 도착 시각 | CPU 버스트 |
| --- | ---: | ---: |
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 2 |

| 실행 구간 | 실행 프로세스 | 해당 구간 종료 후 남은 CPU 시간 |
| --- | --- | ---: |
| 0–3 | P1 | 5 |
| 3–6 | P2 | 1 |
| 6–8 | P3 | 0 |
| 8–11 | P1 | 2 |
| 11–12 | P2 | 0 |
| 12–14 | P1 | 0 |

| 프로세스 | 최초 실행 | 종료 | 응답 시간 | 반환 시간 | 대기 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| P1 | 0 | 14 | 0 | 14 | 6 |
| P2 | 3 | 12 | 2 | 11 | 7 |
| P3 | 6 | 8 | 4 | 6 | 4 |

예를 들어 P2의 응답 시간은 3 − 1 = 2, 반환 시간은 12 − 1 = 11, 대기 시간은 11 − 4 = 7입니다.
P3의 CPU 버스트가 더 짧더라도 P2보다 나중에 준비 큐에 들어왔으므로 P2가 먼저 실행됩니다.

## 8. 스레드와 동기화

같은 프로세스의 스레드는 주소 공간과 여러 자원을 공유하지만, 각자 레지스터 상태와 스택 등의 실행 문맥을 가집니다.
공유 데이터에 대한 여러 연산이 겹치고 실행 순서에 따라 결과가 달라지는 상황을 경쟁 상태라고 합니다.

임계 구역은 공유 자원에 접근하는 코드 구간입니다. 공유 데이터의 일관성을 위해 적절한 동기화가 필요합니다.

| 도구 | 주요 용도 |
| --- | --- |
| 뮤텍스 | 한 번에 하나의 실행 흐름만 보호된 구간에 들어가도록 함 |
| 세마포어 | 카운터와 대기 연산을 이용해 자원 개수나 실행 순서를 조정함 |
| 조건 변수 | 특정 조건을 기다리는 스레드가 잠들고 조건 변화 시 다시 확인하도록 함 |

조건 변수를 이용해 깨어난 스레드는 뮤텍스를 확보한 뒤 조건을 다시 검사해야 합니다.
동기화는 경쟁 상태를 막는 데 도움이 되지만, 락의 획득 순서가 일관되지 않으면 교착 상태가 발생할 수 있습니다.

## 9. 교착 상태

교착 상태는 여러 실행 주체가 서로가 보유한 자원 등을 기다려 진행할 수 없는 상태입니다.
고전적인 자원 할당 모델에서 다음 네 가지는 교착 상태가 발생하기 위한 필요조건입니다.

1. **상호 배제**: 특정 자원을 동시에 공유할 수 없음
2. **점유 대기**: 자원을 보유한 채 추가 자원을 기다림
3. **비선점**: 자원을 보유자로부터 임의로 회수할 수 없음
4. **순환 대기**: 서로의 자원을 기다리는 순환 관계가 존재함

예방은 이 조건 중 하나 이상이 성립하지 않게 설계하는 방법입니다. 예를 들어 모든 락의 획득 순서를 정하면 순환 대기를 막을 수 있습니다.
회피는 자원 요청을 허용해도 안전 상태를 유지하는지 판단하는 방법이고, 탐지와 회복은 교착 상태를 찾아 해소하는 방법입니다.

기아는 특정 작업이 계속 실행 기회를 얻지 못하는 현상으로, 교착 상태와 구분해야 합니다.

## 10. 가상 메모리와 페이징

가상 메모리는 프로세스가 사용하는 주소를 물리 메모리와 분리해 관리하는 방식입니다.
페이징에서는 가상 주소 공간을 페이지로, 물리 메모리를 프레임으로 나누고 페이지 테이블로 대응 관계와 접근 권한 등을 관리합니다.

| 용어 | 의미 |
| --- | --- |
| 페이지 테이블 | 가상 페이지와 물리 프레임의 대응 관계 등을 기록하는 자료구조 |
| TLB | 최근에 사용한 주소 변환 정보를 보관하는 캐시 |
| 페이지 폴트 | 접근한 페이지의 상태나 권한 등을 이유로 정상적인 메모리 접근을 완료하지 못해 예외 처리가 필요한 상황 |

TLB 미스가 곧 페이지 폴트를 뜻하지는 않습니다. TLB에 정보가 없어도 페이지 테이블에 유효하고 허용된 매핑이 있으면 주소 변환을 계속할 수 있습니다.
페이지 폴트는 디스크에서 페이지를 읽어오는 경우 외에도 발생할 수 있으며, 처리 결과는 원인에 따라 매핑 준비, 접근 거부, 프로세스 종료 등으로 달라집니다.
